# Project continuity

User preference: end every response that completes a request with a brief Arabic
handoff: what was completed, anything still pending, and one concrete next step
with its purpose. Keep it short; do not invent extra work when the request is done.
Distinguish a proposed next step from work already authorized or completed.

Read `HANDOFF.md` when returning to the project after a break. After substantive
work, update it with the current outcome, relevant verification and its date,
unresolved issues, and the next useful step. Preserve unrelated local changes.
Use the handoff to avoid repeating completed investigations or running commands
without a specific purpose. Verify current state when needed; historical test
results are not evidence that tests were rerun today.
